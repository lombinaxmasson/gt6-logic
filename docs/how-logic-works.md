# 这些元件在算什么

写给做这个附属的人。玩家看到恒温器和浮球开关就够了；改代码时需要对上计组里的几个词。用得上的只有电平、组合逻辑、时序逻辑。方块名单在 [`components.md`](components.md)。

## 线上跑的是一个数

信号线里的一个值，单位是 `GtSignalCarrier.UNIT`。一级原版红石等于 `1 UNIT`，也就是 `Integer.MAX_VALUE`。满信号是 `15 UNIT`。中间可以是半级，所以它比红石粉细。

这个数有两种用法：

- **开关量。** 只有 `0` 和 `15 UNIT`。恒温器、浮球开关、厨房定时器、联锁开关都输出这种。计组里叫数字量，这里就是开和关。
- **连续量。** `0` 到 `15 UNIT` 之间的任意值。电表报出的电量比例、比例控制器算出的开度、调节阀吃进去的开度，都是这种。数电课通常假设信号已经是 0 和 1；“开多大”在这里是另一类问题，所以分数要留着。

原版红石粉只能看见 0–15 的整数，而且向上取整。半级到了粉上已经是 1 级。精细值只活在信号线里。信号表就是把这个分数显示出来。

指示灯和报警铃只看、不往回写。灯若也对外输出，线读到灯，灯又被线点亮，自己咬自己的尾巴。所以这两块是纯接收端，实现 `GtSignalReceiver`。会输出的方块只实现 `GtSignalSource`。

指示灯取六个邻居里最强的一路，向上取整至少 1 级就亮。报警铃只听自己朝向的那一面。设定级别是 0 到 14，向上取整后的级别必须比它大才响，刚好等于设定值时保持安静。正在响的时候每秒响一声；安静下来之后再超过，下一拍就响。

后面说「够」，都是同一条线：向上取整至少 1 级。联锁、延时、计数都用它来决定开和关。信号表和选择开关则把分数留着。

延时继电器听正面。推迟出现：连续够的第 N 个 tick 才开，中间断了从头数。推迟消失：一够就开，不够之后再保持 N 个 tick。玩家设的是 1、2、5、10、20、30、60 秒。

计数器的正面数上升沿，背面的上升沿清零。数满开是从关到开之后锁住，数满关是从开到关之后锁住。目标和模式一改，次数就回到这个模式的初态。

联锁的正面和背面是两路。与、或、非是同一块上的模式，非只看正面。没有记忆。

信号表只听正面，表盘上是四位小数，四舍五入。半级显示 `0.5000`。它不往外送。

补偿中继器把正面的值加上 `UNIT / range`。距离只有两档：16 是红合金和流明，64 是信素。输入是 0 时不加，因为减没了的一跳和没有信号分不清。

选择开关在六个面里选一面，其余五面原样送出这一面的数，包括小数。档位是右键拧的，新放下去时选中贴着的那一面。

厨房定时器的方块不读邻居，六个面一起开或关。右键按秒循环，默认开 10 秒、关 10 秒。1 秒是 20 tick，放下去的第一拍就是开。

算术模块的正面和背面是两路，其余面送出结果。减出来的负数夹成 0。缩小一半是整数除法，只看正面。

配比控制器只用正面做参考。默认第二路 = 第一路 × 2，右键还有 4、1、1/2、1/4。

比例控制器正面是测量，背面是设定，默认冷却。开度是正的偏差乘增益，增益是 1、2 或 4。零和负的偏差都是关。

程序控温器的曲线是 52、63、72、78 °C，每段半分钟，然后停在 78。增益固定是 1。正面读温度。

可编程模块把一行公式按“级”算。内部 1 级是 10000，所以 `0.5` 是准的。`a` 是正面，`b` 是背面。算不出来这一拍就是 0。右键在四行预设里转，打字留到以后。

温度信号：0 是 0 °C，满信号是 150 °C。10 °C 是 1 级。邻居实现 `TemperatureSource` 时用它报的毫摄氏度，否则把信号译回来，向下取整。本体坩埚没有这个接口，恒温器读不到它。

电表自己存 10240 EU，六个面把 `储存 / 容量` 编成信号。100% 是满信号。从信号译回万分比向下取整，满信号的一半译回去是 4999。电表句子不绕这一圈，直接用缓冲里的数。

电动阀够了每拍 250 mB，并且每拍 1 EU，没电就关。调节阀不耗电，流量是 `信号 × 250 / (15 UNIT)` 向下取整，一半信号是 124 mB。泵用同一套比例，满信号每拍 1000 mB，流量大于 0 才花 1 EU。进出口在朝向轴上，信号看另外四面里最强的。它们自己不存流体。

可调加热器只听朝向那一面。满信号每拍花 32 EU，并把花掉的数量作为 HU 供这一拍抽走，下一拍换成新的。可调冷却器同样，提供的是 CU。推荐的 HU、CU 输出大小是 1。

浮球开关朝向储罐。默认低于 20% 开，高于 80% 关。没有流体能力时读数是 0，补水档会打开。储罐是 16 桶。

## 组合逻辑

组合逻辑没有记忆。这一拍输入定了，输出就定了，下一拍不记得上一拍。

| 方块 | 在算什么 |
|---|---|
| 联锁开关 | 与：两路都够才开。或：任一路够就开。非：有就关、没有就开。三档是同一块方块上的模式 |
| 算术模块 | 加、减、缩放、取最大、取最小 |
| 可编程模块 | 还是上一行，只是把运算写成一行公式。每一拍算一遍，没有“运行到第几行” |
| 选择开关 | 多路选择器。档位是人手拧的，选出哪路就把哪路的数原样送出 |
| 补偿中继器 | 输出 = 输入 + 这一跳被线减去的量。线每过一格减 `UNIT / range` |
| 电表 | 把自己统计到的电量比例写成这一拍的连续量 |

## 时序逻辑

时序逻辑有记忆。同样的输入，以前的状态不同，输出就可以不同。这里每种记忆都是一块专门的方块。

### 回差

只设一个门槛时，温度在 32 °C 附近晃一下，加热器就会反复开关。数电里这叫在门槛上振荡。

回差给两个门槛，并记住上次是开还是关。低于 30 °C 开，高于 35 °C 关，中间保持原样。这 1 位记忆的教材名字是施密特触发器。恒温器、浮球开关、蓄电池管家共用这段判定，只是读数分别是温度、液位、电量。

加热、补水、补电：太低了就开。冷却、排放：太高了就开。记忆的方式相同，门槛的方向反一下。输出仍是开关量。

### 节拍

厨房定时器自己产生“开一会儿、关一会儿”，不看邻居。教材里的时钟是给别人对齐用的方波；玩家这里只设定开几秒、关几秒。相位从 0 开始，放下去的第一拍就是开。

程序控温器是带着曲线的节拍：这一段该是 52 °C，下一段该是 63 °C。它写出的是加热或冷却该开多大，是连续量。

### 延时

延时继电器记住「还要再等多少 tick」：

- 推迟出现：信号来了先数，数满才开。用来按顺序开机。
- 推迟消失：信号走了先保持，再关上。

玩家看到的单位是秒。1 秒是 20 tick。

### 计数

计数器记住已经来过多少个上升沿，数到设定的次数再锁住。复位是背面的另一个上升沿。这是唯一把「次数」放进状态的方块。

## 慢一拍

信号线和元件谁先 tick 并不固定。元件若在被采样的同时改输出，线会读到算到一半的数，方块放置顺序一变，结果也变。

做法和寄存器打一拍一样。这一拍算出来的数先放在待发布。`gtSignal` 只让别人读上一拍已经发布的数，tick 末尾再抄过去。对外固定慢一拍，于是和谁先跑无关。

读邻居也只发生在自己的 tick 里。比例控制器若在 `gtSignal` 里面再去读线，会碰上线正在采样、自己的输出暂时是 0。所以 `gtSignal` 是纯读取。

## 连续量和开关量各管一段

发酵罐的窗口宽。恒温器贴在罐上：低于 30 °C 打开加热，升过 35 °C 关掉，中间保持。罐有热惯性，温度不会在关火的同一拍掉回去。这段来回就是回差在挡振荡。指示灯贴在旁边，只显示加热有没有开。

硝化釜会越热反应越快、越快越热。只在一个温度上开关冷却，要么冷得停反应，要么热得压不住。比例控制器看偏差：比设定高得越多，冷却开得越大。调节阀把这个连续量变成流量。在这之前，分数主要用来保住衰减和电表读数，不被红石取整吃掉。

配比控制器是乘一个系数，例如空气流量 = 燃料流量 × 系数。算术模块里的缩放是同一件事，配比只是把这个用途做成一块看得懂的方块。

蓄电池管家要的是“现在有几成电”。电表串在线路上，把这个比例写成连续量。管家再拿它做回差：低于 20% 开下一台发电机，回到 90% 再关。管家自己不去翻电池的内部对象。
