# 这些元件在算什么

写给做这个附属的人。玩家看到的是调节阀、比例控制器和记录仪；改代码时需要对上计组里的几个词。用得上的只有电平、组合逻辑、时序逻辑。方块名单在 [`components.md`](components.md)。

## 线上跑的是一个数

信号线里的一个值，单位是 `GtSignalCarrier.UNIT`。一级原版红石等于 `1 UNIT`，也就是 `Integer.MAX_VALUE`。满信号是 `15 UNIT`。中间可以是半级，所以它比红石粉细。

这个数有两种用法：

- **开关量。** 只有 `0` 和 `15 UNIT`。开关量的门、锁存、计时、计数交给 ProjectRed。
- **连续量。** `0` 到 `15 UNIT` 之间的任意值。比例控制器算出的开度、调节阀吃进去的开度，都是这种。数电课通常假设信号已经是 0 和 1；“开多大”在这里是另一类问题，所以分数要留着。

原版红石粉只能看见 0–15 的整数，而且向上取整。半级到了粉上已经是 1 级。精细值只活在信号线里。信号表就是把这个分数显示出来。

GT6 本体的传感器面板能测液位、温度、电量、进度等，百分比和缩放模式会输出连续的 0–15，但没有小数。需要小数时，让本模组的元件读 GT 线，或者把 GT 传感器的整数级再换算成细值。

## 端口

会输出的方块只实现 `GtSignalSource`。只看不写的仪表实现 `GtSignalReceiver`，避免把读数送回信号线。

连续量模块是贴地板：贴地放，输出在玩家朝向那一侧，左右和后是输入。规则在 [`GatePorts`](../src/main/java/com/lombinaxmasson/gt6logic/block/GatePorts.java)。执行器只从出口朝向的左侧读一路信号。

## 连续量模块

算术模块的左右是两路，正面送出结果。减出来的负数夹成 0。缩小一半是整数除法，只看正面。

配比控制器只用背面做参考。默认第二路 = 第一路 × 2，右键还有 4、1、1/2、1/4。

比例控制器左面是测量，右面是设定，默认冷却。开度是正的偏差乘增益，增益是 1、2 或 4。零和负的偏差都是关。

可编程模块把一行公式按“级”算。内部 1 级是 10000，所以 `0.5` 是准的。`a` 是左，`b` 是右。算不出来这一拍就是 0。右键在四行预设里转，打字留到以后。

## 细值工具

信号表只听正面，表盘上是四位小数，四舍五入。半级显示 `0.5000`。它不往外送。

补偿中继器把正面的值加上 `UNIT / range`。距离只有两档：16 是红合金和流明，64 是信素。输入是 0 时不加，因为减没了的一跳和没有信号分不清。

捆绑线缆接口把 GT 线的 0–15 UNIT 和 ProjectRed 捆绑线缆一种颜色的 0–255 互换。同一根线缆可以串多个接口，各管一色。

## 执行器

调节阀不耗电，流量是 `信号 × 250 / (15 UNIT)` 向下取整，一半信号是 124 mB。泵用同一套比例，满信号每拍 1000 mB，流量大于 0 才花 1 EU。进出口在朝向轴上，信号只看出口朝向的左侧。它们自己不存流体。

它们往邻居的 `IFluidHandler` 抽送。GT6 的流体管道和储罐都注册了这个能力，所以可以直接接。管道朝向阀的那一面要先用扳手接通，否则管道的面处理器会拒绝填充。GT 机器的进液面也要对好。

## 控制室

指针表把 0 到满信号画成不到一整圈，满信号和 0 不会叠在同一个刻度上。记录仪放下去就记一笔，之后每 20 tick 记一笔，只留最近 60 笔里的最低和最高。

## 慢一拍

信号线和元件谁先 tick 并不固定。元件若在被采样的同时改输出，线会读到算到一半的数，方块放置顺序一变，结果也变。

做法和寄存器打一拍一样。这一拍算出来的数先放在待发布。`gtSignal` 只让别人读上一拍已经发布的数，tick 末尾再抄过去。对外固定慢一拍，于是和谁先跑无关。

读邻居也只发生在自己的 tick 里。比例控制器若在 `gtSignal` 里面再去读线，会碰上线正在采样、自己的输出暂时是 0。所以 `gtSignal` 是纯读取。
