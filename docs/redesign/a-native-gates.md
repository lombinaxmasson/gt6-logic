# 方案 A：GT 原生的门

> 状态：**未采用**，选了 [`b-projectred-bridge.md`](b-projectred-bridge.md)。端口规则（第 1 节）仍是方案 B 里连续量模块的依据。共用的问题和事实见 [`README.md`](README.md)。

## 0. 目标

GT6 Logic 自己提供一套能组合的门，直接接 GT6CE 信号线，不依赖别的模组。门的端口规则照 ProjectRed：门贴在一个面上，端口是这一面上的四个侧面，放置时定方向，可以关掉不用的输入。和 ProjectRed 的区别是门里传的是 GT 的精细信号，连续量模块也用同一套端口。

完成的标准不是方块数量，而是这三条电路能在生存世界里照着摆出来：

1. 两个拉杆各接一张线网，进同一个与门，与门的输出点亮指示灯。
2. 与门直接贴着非门，非门输出点灯。两个门之间不用线。
3. 半加器：两路输入各分出去两次，同时进异或门和与门，得到和与进位。

## 1. 一个门怎样收两路信号

### 1.1 形态

门是一格空间里的一块薄板，贴在一个实心面上，像中继器。门有两个方向属性：

- `support`：从门指向它贴着的方块。第一步只做地面，`support = DOWN`。墙和天花板在第二步加，规则不变。
- `rotation`：0 到 3，决定输出朝哪。放置时输出背向玩家，和 ProjectRed、原版中继器一致。

贴着的那根轴（上和下）**不是端口**。端口只在板面的四个侧面上。

### 1.2 四个侧面

每个门有四个相对侧面：

| 编号 | 名字 | 放在地上、玩家朝北放下时 |
|---|---|---|
| 0 | 前 | 北 |
| 1 | 右 | 东 |
| 2 | 后 | 南 |
| 3 | 左 | 西 |

相对侧面到世界方向的换算只写在一个类里（暂名 `GatePorts`），所有门都用它。墙面和天花板时，“顺时针”按从门外看向支撑面算。

每个门种类给四个侧面各定一个角色：输入、输出或不接。双输入门的默认表是：

| 侧面 | 角色 |
|---|---|
| 前 | 输出 |
| 右 | 输入 B |
| 后 | 不接（可以打开当输入 C） |
| 左 | 输入 A |

这就是“一个元件怎样进两个信号”：**左和右是两路输入，前面送出结果，后面默认空着。** 两路输入在门的两侧，接在上面的两张线网互不相连，GT 信号线就不会把它们合并成一个最大值。

### 1.3 读和写

- **读输入**：只读角色是输入的侧面。读法沿用 [`SignalInputs.read`](../../src/main/java/com/lombinaxmasson/gt6logic/signal/SignalInputs.java)：GT 线读精细值，另一个门读它已发布的 `gtSignal`，其他方块读原版红石。
- **写输出**：只有输出侧面有值。`gtSignal(side)` 只在 `side` 等于“从输出侧邻居指向本门”的方向时返回结果，其余五个面返回 0。原版 `getSignal` 同样只在输出侧不为 0。
- 输入侧面永远是 0，接在输入上的线读不到门自己的输出，不会自激。
- 门不实现 `GtSignalReceiver`。实现了的话 GT 线会整块跳过它，输出侧也读不到。

### 1.4 时序

沿用现有的信号双缓冲（[`SignalBlockEntity`](../../src/main/java/com/lombinaxmasson/gt6logic/signal/SignalBlockEntity.java)、[`PublishedSignal`](../../src/main/java/com/lombinaxmasson/gt6logic/signal/PublishedSignal.java)）。每个门在自己的 tick 里读输入、算出结果、放进待发布，tick 末尾再发布。每过一个门慢 1 tick，和放置顺序无关。三个门串起来就是 3 tick。

### 1.5 门接门

门 A 的前面贴着门 B 的后面（或左、右）时，B 直接读 A 的 `gtSignal`。按 1.3 的规则，A 只在朝 B 的那一侧送值，B 只在输入侧读，所以一个方向只有一条路，不需要线。

一路信号要分给两个门时，用一张 GT 线网同时贴住两个门的输入侧。线网取最大值，对单个源来说就是原样分发。

### 1.6 接线

GT 信号线放下时只连向被点的那一面。所以玩家接门的做法是：**手持信号线，点门的输入侧面**，线就放在门旁边并连向门。线网其余的连接用 GT 的线缆工具照常接。

文档、门的贴图、放大镜读数都要让玩家看得出哪一侧是哪个端口（见第 3 节）。

### 1.7 支撑

`canSurvive` 要求支撑面是实心的。支撑方块被拆掉，门掉落成物品，和中继器一样。

## 2. 调整

SDK 的 `AddonTool` 只有锹和放大镜，没有螺丝刀，所以本模组带一把自己的螺丝刀（`gt6logic:screwdriver`）：

- 螺丝刀右键：输出顺时针转一格。
- 螺丝刀潜行右键：换一种输入组合。双输入门依次是：左右、左右后、左后、右后。
- 空手右键：在聊天栏报这个门的种类、每个端口的当前值和输出。
- 放大镜右键：同上，并附精细值。
- 门本身的设置（计时长度、计数目标、运算种类）用空手潜行右键循环。需要输入数字的门第五步再做界面。

GT6CE 把螺丝刀加进 SDK 之后，GT 的螺丝刀也认。

## 3. 外观

- 板面上画一个箭头指向输出侧。每个启用的输入侧有一个小灯点，输出侧有一个。
- 输入大于 0 时那一侧的灯点亮，输出为开时箭头亮。
- 禁用的侧面不画灯点。
- 方块状态：`rotation`（4）、`output`（2）、`input_left`、`input_right`、`input_back`（各 2），用 multipart 模型叠加，不为每个组合写一个模型。墙面加 `support` 之后再翻 6 倍。

## 4. 门的种类

### 4.1 第一步

只做下面几种，先把端口、摆放、测试这一层做实。

| 门 | 输入 | 输出 |
|---|---|---|
| 非门 | 后 | 后面不够时为开 |
| 与门 | 左、右（可加后） | 所有启用输入都够时为开 |
| 或门 | 左、右（可加后） | 任一启用输入够时为开 |

“够”沿用现在的定义：向上取整至少 1 级。开是 `15 * UNIT`，关是 0。

另外需要两块输入输出：

- 拉杆：已有的大号拉杆不用改，它六面输出、没有输入。
- 指示灯：已有，六面都读，不输出。

### 4.2 之后

按同一张端口表加，每种都写清四个侧面的角色：

- 开关量：异或、与非、或非、同或、RS 锁存（左置位、右复位、前输出）、延时（后入前出）、脉冲、计时器（无输入，前输出）、计数器（后计数、左复位、前输出）、选择器（左 A、右 B、后选择、前输出）。
- 连续量：算术（左 A、右 B、前结果，后选运算或不接）、比较、比例控制（左测量、右设定、前开度）、配比（后参考、前结果）、公式（左 `a`、右 `b`、后 `c`、前结果）。

现有的纯逻辑类（[`control/`](../../src/main/java/com/lombinaxmasson/gt6logic/control/) 下的 `Interlock`、`Arithmetic`、`Formula`、`HysteresisSwitch`、`PulseCounter`、`ProportionalControl` 等）保留，它们没有方向问题。重做的是方块和方块实体。

### 4.3 传感器和执行器

传感器只有一个读数，不需要端口表：

- 浮球开关、恒温器、蓄电池管家照旧贴在机器上，朝机器那一面读。输出改成**只在背离机器的那一面**，这样在它外面接线、接门都只有一种接法。
- 阀、泵沿用进出口轴，信号从另外四个面里任一面进来，不变。

## 5. 现有代码怎么处理

如果还没有对外发布过，旧方块直接删除，不做存档迁移。

- 保留：信号双缓冲、`SignalInputs`、`control/` 下的纯逻辑、储罐、能量缓冲、阀和泵、电表、控制室里的显示类方块。
- 重写：`LogicPlateBlock` 和所有把 `FACING` 与反方向当两路输入的方块（联锁、算术、可编程、比例、配比、计数器、延时继电器、选择开关、补偿中继器）。
- 删除：把门悬空放置、用探针喂输入的 GameTest。

## 6. 测试

### 6.1 端口换算（JUnit）

- 每种 `support` 乘 4 种 `rotation`，前、右、后、左是四个不同的方向，并且都垂直于 `support`。
- 转一格以后，原来的右变成前。
- 放在地上、玩家朝北，前是北，右是东。

### 6.2 真实摆放（GameTest）

不再用 `setBlockAndUpdate` 放门和线。每个方块都由模拟玩家拿在手里、朝着某个面使用放下去，经过 `getStateForPlacement` 和 `canSurvive`。线也这样放，点在门的输入侧面上。输入用拉杆，输出读指示灯的亮灭。

必须过的电路：

1. 两拉杆、两线网、与门、一线网、指示灯。四种开关组合对照真值表。
2. 同上换成或门。
3. 与门前面直接贴非门，非门点灯。两个门之间没有线。
4. 半加器：两路输入各接一张线网，每张线网同时碰到异或门和与门的输入侧。和、进位各点一个灯。
5. 拆掉门下面的支撑块，门掉落；拆掉一根输入线，那一路变成 0。
6. 往输出侧接一张线网，再从这张线网接回同一个门的输入，门不会把自己锁住。
7. 用螺丝刀旋转之后，原来的输入线不再起作用，新的输入侧开始起作用。

### 6.3 客户端检查

每一步合并前，在客户端照第 0 节的三条电路实际摆一遍，截图放进那一步的卡片计划里。

## 7. 顺序

1. `GatePorts`、门的底座方块和方块实体、螺丝刀、非门、与门、或门，只做地面。6.1、6.2 的第 1、3、5、7 条通过。
2. 墙和天花板。异或等其余组合门、锁存、延时、计时、计数。6.2 全部通过。
3. 连续量门按新端口重做，删除旧的板子。
4. 传感器只在背离机器的一面输出。
5. 计时、公式这些需要输入数字的门做界面。复制设置。

## 8. 风险

- 门的渲染和交互是从零开始做，好不好用要靠客户端反复试。ProjectRed 的门已经打磨了很多年。
- GT 线一张网只有一个数，没有总线。要做多路信号得另外设计，这一版不做。
- 没有 SDK 的螺丝刀，自带一把会和 GT 的工具习惯不一致。
