# 方案 B：ProjectRed 和 GT6CE 的衔接

> 状态：**已选定**。方案 A 不再做。第 7 节第 0 步的验证已完成，结果见第 3.1 节。共用的问题和事实见 [`README.md`](README.md)。

## 0. 目标

GT6 Logic 改成：**让 GT6CE 的线缆和机器成为 ProjectRed 电路的一部分。**

ProjectRed 已经有贴面的门、红合金线、捆绑线缆、计时器、计数器、锁存器、集成电路，端口和摆放规则也是玩家熟悉的。这些本模组不再自己做，做了也只会是下位替代。

本模组做 ProjectRed 够不到的那一半：

1. **GT 线缆进 ProjectRed 电路。** GT6CE 有三种信号线，每种都有裸线和绝缘线缆两种：红合金（16 格）、信素（64 格）、流明（16 格，会发光）。它们和 ProjectRed 的线、门贴着就能互相传信号，不用转接块。ProjectRed 管一个房间里的逻辑，房间之间用信素线缆拉主干。
2. **GT 线上的小数进 ProjectRed。** GT 线的信号带小数，原版红石只有 0–15，ProjectRed 捆绑线缆每色有 0–255。捆绑线缆接口把 GT 线的精细值放到一种颜色上，液位、温度、电量能精确地走一根线缆。
3. **ProjectRed 没有的连续量运算。** 比较、比例、配比、公式。
4. **GT 机器的进出口。** 读机器的传感器，开关流体和热量的执行器。

完成的标准是这条电路能在生存世界里照着摆出来：

> 储罐上的浮球开关、发酵罐上的恒温器，各接一根 ProjectRed 红合金线，进一个 ProjectRed 与门。与门的输出接电动阀。水位低并且温度够的时候阀打开。

## 1. 分工

| 谁做 | 什么 |
|---|---|
| ProjectRed | 开关量的门（与、或、非、异或、锁存、计时、计数、选择等）、红合金线、绝缘线、捆绑线缆、指示灯、集成电路 |
| GT6CE | 机器、流体、能量、GT 信号线（精细值，一张网一个数，长距离） |
| 本模组 | 传感器、执行器、捆绑线缆接口、连续量模块、看精细值的仪表 |

## 2. 一个元件怎样收两路信号

在这个方案里，第一个双输入元件就是 **ProjectRed 的与门**，本模组不做它。本模组要保证的是：自己的传感器能当它的输入，自己的执行器能接它的输出。

```text
浮球开关 --红合金线--> 与门左侧
恒温器   --红合金线--> 与门右侧
                       与门前面 --红合金线--> 电动阀
```

这要求本模组的方块满足：

- **传感器只在一个面输出**：背离机器的那一面。ProjectRed 的线贴在这一侧时连得上，其余面不连。现在的传感器往五个面送，会把旁边的线也带上。
- **对原版红石可见**：ProjectRed 的线和门读的是原版红石（0–15）。传感器的 `getSignal` 在输出面给出向上取整后的级别，`canConnectRedstone` 只在输出面为真。
- **执行器从原版红石读信号**：电动阀够 1 级就开。调节阀、泵把 0–15 当比例。
- **一个方块只接一路**：传感器只有一个输出，执行器只有一路信号输入。需要两路的东西交给 ProjectRed 的门。

本模组自己仍有几块双输入的连续量模块（第 5 节）。它们必须用和 ProjectRed 门一样的端口规则：贴地放、输出在玩家朝向那一侧、左右是输入。规则见 [`a-native-gates.md`](a-native-gates.md) 第 1 节，这里只做连续量那几块，不做开关量门。

## 3. 两种线的转接

### 3.1 单路：已验证，直接互通

`ProjectRedInteropTests` 和 `ValveTests.projectRedGateDrivesElectricValve` 在 ProjectRed 4.23.0 下验证了这些。ProjectRed 的门和线都用模拟玩家拿物品点放：

| 连法 | 结果 |
|---|---|
| 红石块 → GT 线 → ProjectRed 非门输入 | 门翻转 |
| ProjectRed 非门输出 → GT 线 | GT 线读到 15 级，减一格线损 |
| 红石块 → ProjectRed 红合金线 → GT 线 | GT 线有信号 |
| 红石块 → GT 线 → ProjectRed 红合金线 → 非门输入 | 门翻转 |
| ProjectRed 非门输出 → 本模组电动阀 | 门开阀开，门关阀停 |
| 先放门，再在门前放 GT 线 | GT 线自动接上门 |
| 先放 GT 线，再在旁边放门 | **接不上**，见下 |

所以不做单路转接块。GT 线进 ProjectRed 时按原版规则向上取整成 0–15，小数在这一步丢掉，要保留小数走第 3.2 节。

GT 线只在自己被放下的那一刻接通旁边的方块。之后在它旁边放的门，GT 线不会补接，要用 GT 的工具手动接通。这是 GT 线对所有邻居的规则，本模组只用 SDK 改不了，要么写进游戏说明（先放门再放线），要么向 GT6CE 提议让信号线在邻居变化时重新接线。`gtWireDoesNotJoinALaterGate` 记着这个现状，GT 改了它就会失败。

另外，ProjectRed 的门按玩家头部朝向决定前方：玩家朝东放，输入在西，正面朝东。

### 3.2 捆绑线缆接口

GT 线一张网只有一个数，ProjectRed 的捆绑线缆有 16 色。接口块把一种颜色和一根 GT 线对接：

- 一面实现 `IBundledTile`，接捆绑线缆。另一面接 GT 线。
- 潜行右键选颜色，右键选方向（线缆到 GT，或 GT 到线缆）。
- 线缆到 GT：读这一色的 0–255，换算成 `值 × 15 UNIT / 255` 送上 GT 线。
- GT 到线缆：读 GT 线的精细值，换算回 0–255，只占这一色，其余颜色是 0。
- 同一根捆绑线缆上可以串多个接口，各管一色。

## 4. 传感器和执行器

保留并改造现有的这些：

| 方块 | 读什么 | 输出 |
|---|---|---|
| 浮球开关 | 贴着的流体能力 | 背离机器的一面，开或关 |
| 液位计（新） | 同上 | 同一面，液位按比例给 0–15，同时给 GT 精细值 |
| 恒温器 | `TemperatureSource` 或温度信号 | 背离机器的一面，开或关 |
| 电表 | 自己的 10240 EU 缓冲 | 一个固定的输出面，比例 |
| 蓄电池管家 | 电表的读数 | 开或关 |
| 电动阀、调节阀、可调泵 | 侧面的原版红石或 GT 线 | 流量 |
| 可调加热器、冷却器 | 朝向面的原版红石或 GT 线 | HU、CU |

之后再加一块**机器总线接口**：贴在一台机器上，把几种读数（液位、电量、是否在工作）放进一根捆绑线缆的不同颜色。能读到哪些取决于 SDK 开放了什么，现在只能确定流体能力和本模组自己的电表。

## 5. 连续量模块

ProjectRed 的信号只有 0–15。比例控制、配比、公式需要小数，留在 GT 线上做：

| 模块 | 左 | 右 | 后 | 前 |
|---|---|---|---|---|
| 算术 | A | B | 不接 | 结果 |
| 比例控制 | 测量 | 设定 | 不接 | 开度 |
| 配比 | 不接 | 不接 | 参考 | 结果 |
| 公式 | `a` | `b` | `c` | 结果 |

这些模块读写 GT 线。要接进 ProjectRed 时经过第 3 节的转接。

## 6. 删掉什么

ProjectRed 已经有的，本模组删掉：

- 指示灯、警示灯塔、控制台面板：ProjectRed 照明模组有灯。
- 延时继电器、计数器、联锁开关、选择开关、厨房定时器：ProjectRed 集成模组有对应的门。
- 大号拉杆、带标签的按钮、紧急停止：原版拉杆、按钮和 ProjectRed 的门够用。
保留：信号双缓冲、`SignalInputs`、`control/` 下的纯逻辑、储罐、能量缓冲、阀、泵、加热器、冷却器、电表、补偿中继器（GT 线做长距离主干时补线损）、信号表、数码管、指针表、记录仪（这几块用来看 GT 线上的精细值）。

如果还没有对外发布过，删掉的方块不做存档迁移。

## 8. 构建

- 开发运行用的五个 jar 由 `fetch-projectred.ps1` 从 Modrinth 下到 `libs/projectred/`，按 SHA1 校验，不进仓库。`build.gradle` 用 `localRuntime fileTree(...)` 引用，不打进成品。目录为空时（比如 CI）跟 ProjectRed 有关的 GameTest 直接跳过。
  - 不走 Gradle 的 maven：covers1624 maven 上找不到 1.21.1 的 ProjectRed 坐标；Modrinth maven 从 Gradle 连接时 TLS 握手被断开，PowerShell 直接下载正常。
- 版本钉在 ProjectRed 4.23.0 在 Modrinth 上声明的那一组：ProjectRed core、integration、transmission 4.23.0，CB Multipart 3.5.0.155，CodeChicken Lib 4.6.1.529。
- 编译依赖等第 2 步做捆绑线缆接口时再加。到时要找能用的 ProjectRed 接口包来源；1.21.1 是官方映射，不需要 `fg.deobf` 那类转换。
- `neoforge.mods.toml` 里 ProjectRed 写成必需依赖。做成可选依赖会让一半方块在没装 ProjectRed 时没用，先不做。

- 玩家要多装四个模组。只想玩 GT6CE 的人用不了本模组。
- 跟着 ProjectRed、CB Multipart、GT6CE 三方的版本走，任何一方大改都要跟。

- 客户端还没进过，渲染和交互上的冲突还不知道。
