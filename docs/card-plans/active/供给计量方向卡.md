## 0. 它解决什么

本模组同时站在 GT6CE 和 ProjectRed 之间。前一版把大量方块做成了这两者的下位替代：ProjectRed 已经有的开关量门，GT6 本体已经有的传感器和覆盖板。结果是“每块都能用，但没有一块非它不可”。

这张卡把定位收成一条只属于本模组的线：**GT6 机器的供给计量层**。不重复测量，不重复开关控制，只补两者都没有的连续量。

分工：

| 谁 | 负责 |
|---|---|
| ProjectRed | 开关量的门、锁存、计时、计数、选择、密集线缆 |
| GT6CE | 机器、材料、流体与能量、传感器面板、覆盖板、开关量机器控制 |
| 本模组 | 细值（带小数的信号）、回差、比例执行、连续量运算、历史读数、GT 与 ProjectRed 的细值转接 |

## 1. 已验证的事实

### 1.1 GT6 本体已经覆盖的部分

对照 GT6CE 源码 `c899462a`（与 `libs/gt6ce/build-commit.txt` 一致）：

- **21 种传感器**，8 种模式：显示、百分比、大于、等于、小于、缩放、满、未满。其中 **百分比和缩放会输出连续的 0–15**，不只是阈值开关。每 10 tick 采样一次，扳手可以换输入面，输出在除输入面外的五个面。
- 可测：流体量/容量、物品数/容量、GT 电线瓦数、本体机器进度、坩埚温度、传动轴、重量、桶、gibbl、堆数、亮度、玩家数、时间、反应堆辐射、激光、TPS。
- **覆盖板**覆盖了大量开关控制：红石机器开关、自动/自动红石开关、1–30 分钟定时重启、活动检测（possible/running/processing/success）、能量传感器、进度传感器、红石发射器、覆盖控制器（用红石暂停同一方块上的所有 cover）、三种选择器、shutter（断管断线）、泵/传送带/机械臂（按电压档固定速率）、压力阀（满罐泄压）、过滤、排水、通风。

结论：测量、阈值比较、机器开关、管道开关、定时、防满罐，本体都有。**本体没有的是**：小数信号、回差（双阈值）、按信号连续变化的执行器、连续量运算、历史曲线、GT 细值与 ProjectRed 的转接。

### 1.2 比例执行器能接进 GT 流体系统

`Gt6FluidInteropTests` 在 GT6CE + ProjectRed 的运行时下通过：

- `controlValveFeedsGtFluidPipeAndTank`：本模组储罐 → 调节阀（满信号 250 mB/tick）→ GT `pipe_medium_steel` → GT `drum_bronze`。水出现在 GT 储罐里。
- `signalScalesWhatGtTransportCarries`：同一 tick 窗口里并排跑两套相同回路，一套满信号、一套半信号。满信号的送达量是半信号的 1.5–2.5 倍，说明比例关系穿过了 GT 管道，没有被抹平成开关量。
- `gradlew runGameTestServer`：55 个 GameTest 全部通过。

由此确认的三条规则：

1. **GT 管道的端口要先接通。** 管道的面处理器只在对应连接位为 `true` 时才接受 `fill`；否则返回 0。管道的自动连接只认相邻管道，不认本模组的阀，所以玩家要用扳手把管道朝向阀的那一面打开。
2. **GT 机器走同一个能力。** 所有基础机器都注册了 `IFluidHandler`，按面配置流体输入/输出。阀对着机器的进液面就能送。没有单独跑机器测试，但管道路径和机器路径是同一个能力接口。
3. **限流不等于限速。** 机器有内部缓冲；供给减半会先吃缓冲。只有缓冲耗尽，或面对锅炉、涡轮这类连续消耗者，才会真正改变处理速率。

### 1.3 这条方向的反面证据

可调加热器/冷却器输出 HU/CU，但本体的坩埚和机器不从中抽取。热量这一半目前没有消费者，不能按流体同样的方式宣称成立。

## 2. 方向

产品承诺可以收成一句话：**带死区的传感器 + 连续执行器**。

- **传感器侧**：不重复测量 GT 已经能测的东西。做一个通用死区继电器，读任意红石或 GT 信号（包括 GT 传感器面板的输出），两个阈值，输出细值。需要液位、温度、电量时，让 GT 自己的传感器去量。
- **执行器侧**：只保留 GT 没有的比例执行。优先流体（已验证），热量等有消费者再谈。
- **工具侧**：信号表、补偿中继器、捆绑线缆接口，服务“GT 线拉得长、值带小数”的场景。
- **运算侧**：算术、比例、配比、公式，作为进阶深度，不是入门门槛。
- **可视化侧**：指针表、记录仪。GT 的六格显示只能看当前值，看不到趋势。

按这个标准，现有方块分成三类。具体去留已冻结并执行完毕，见 [`删掉与 GT 重复的方块详细计划`](../closed/删掉与GT重复的方块详细计划.md)：

| 类别 | 方块 | 理由 |
|---|---|---|
| 保留 | 调节阀、可调泵 | GT 没有按信号连续变化的执行器；流体路径已验证 |
| 保留 | 信号表、补偿中继器、捆绑线缆接口 | GT 没有细值读出、线损补偿和 ProjectRed 细值转接 |
| 保留 | 算术、比例、配比、公式 | 本体没有连续量运算 |
| 保留 | 指针表、记录仪 | 本体没有历史曲线 |
| 候选删除 | 可调加热器、冷却器 | 本体已有电热/热流加热器；我们的 HU 没有消费者 |
| 候选删除 | 电表、蓄电池管家 | 本体有电表和机器开关；我们只读自家缓冲，视野更窄 |
| 候选删除 | 浮球开关、恒温器 | 本体有流体/温度传感器和机器开关；独特处只剩回差，由死区继电器取代 |
| 候选删除 | 液位计 | 本体 fluidometer 的百分比模式已经输出连续 0–15 |
| 候选删除 | 电动阀 | 本体 shutter / 机器开关已经能做开关阀 |
| 候选删除 | 储罐 | 本体有储罐；它只是浮球开关的测试夹具 |
| 候选删除 | 数码管 | 本体的六格传感器显示更贴身；我们只多出“读线”一种用法 |

## 3. 明确不做

- 不添加工艺机器。方向是控制层，不是内容机器。
- 不做覆盖板形态。附加 SDK 没有 cover 注册接口，`AddonTool` 也没有螺丝刀/扳手。
- 不做开关量的门、定时、计数。ProjectRed 已经做了。
- 不在热量路径有消费者之前继续投入加热器/冷却器。
- 不做存档迁移。模组还没有对外发布。

## 4. 未决问题

- **热量**：GT 有没有能被外部 HU/CU 驱动的机器？如果没有，加热器/冷却器就删除；如果有，再接一条类似流体的验证。
- **机器限速**：流体限流对带缓冲的批量机器到底有多大影响？需要挑一台连续消耗者（锅炉/涡轮）和一台批量机器各测一次。
- **扳手规则的游戏体验**：GT 管道不会自动接本模组的阀。是写进说明，还是给阀加一个“自动接通相邻管道端口”的辅助？
- **配方与进度**：现在一块配方都没有。接进 GT6 的电压档和组装流程，可能比再加方块更能消除“沙盒玩具”的感觉。
- **ProjectRed 是否必需**：定位上它不是 ProjectRed 的附属；真正需要 ProjectRed 的只有捆绑线缆接口。要不要把它降成可选依赖，让传感器/执行器只依赖原版红石？
- **小数是否真的有人要**：GT 本体给 0–15 的连续量。细值的价值需要一次玩家向的判断，不能只靠技术上的独特性。
